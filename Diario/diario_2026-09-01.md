# Aula 01 (01/09)

**Objetivo.** Refazer um PR fechado do repositório do `scikit-learn`. Escolhemos um PR simples que corrige um bug de validação de dimensões (array shape) em uma das métricas de avaliação. O objetivo era ver se o agente aplicaria a mesma correção que os mantenedores aceitaram.
**Ferramenta.** Claude Code, ~30 min, 3 iterações.
**O que o agente entregou.** O agente rapidamente identificou que matrizes mal formatadas causariam uma exceção de divisão por zero. Ele construiu um bloco `if/else` usando `numpy.ndim` para verificar o formato de entrada e levantou um `ValueError` customizado para alertar o usuário.
**O que mudamos à mão.** Embora o código gerasse a saída lógica correta e passasse num teste isolado, ele quebrava os padrões do repositório. Apagamos a checagem manual do agente e substituímos pela função utilitária interna `check_consistent_length(y_true, y_pred)` que o `scikit-learn` usa globalmente em seus estimadores.
**O que aprendemos.** O agente é excelente para resolver o problema algorítmico imediato, mas muitas vezes não tem a menor ideia do "contexto do repositório" (DRY, utilities, padrões de design). Se não direcionarmos a atenção dele para as funções base do projeto, ele vai reinventar a roda criando código funcional, mas que acumulará dívida técnica.
